## 一、阶段划分（每阶段都有可验证的交付物）

| 阶段 | 目标 | 交付物 | 验收标准 | 前置依赖 |
|---|---|---|---|---|
| **A. 单机可玩骨架** | 手感与循环先立住 | 竖屏适配 + 摇杆 + 相机 + 确定性无限地图 + 视野裁剪 + 自动战斗 + 4 种怪 + 经验升级 + 六阶宝箱 + 装备穿戴 + 本地存档 + **程序自绘的角色与地图外观（A3：八方向小人、按主题分化的装饰、原点营地、小径路网、小地图）** + **A4：账号与昵称（注册/登录/创建角色，昵称跨设备不重复）、1/3 屏卡片式面板（打开不暂停世界）、头像/名牌/经验条 HUD、自动战斗按钮（自动走位）、打击感（斩击/顿帧/震屏）、程序合成音效与 BGM、营地交互入口（治疗/商城/传送）** + **A5：四个技能键（横扫/疗愈/穿刺/旋风，冷却 + 公共冷却 + 手动与自动释放）**（**本阶段的怪暂由本地模拟**，阶段 C 再搬上服务端） | `tools\test-logic.mjs` 断言全绿；抖音 IDE 里能竖屏跑、走 3 分钟不卡不白屏 | **无（可以立刻开始）** |
| **B. 账号与云存档** | 数据不丢、防改包 | `tt.login` → openid 账号；角色/背包/货币服务端化；开箱在服务端抽奖；断线重连 | 两台设备同一账号数据一致；改包改不出更好的掉落 | **已备案域名 + https/wss** |
| **C. 全服共享怪 + 附近玩家可见** | 从"单机"变"真 MMO" | **把怪 AI 与服务端权威模拟搬上服务端** + WebSocket + chunk 订阅（AOI）+ **玩家与怪的快照广播** + **按最高伤害结算奖励** + 坐标校验 | 两端看到同一只怪、同一份血量；击杀后奖励正确归最高伤害者；服务端开销随在线人数增长、不随地图大小增长 | B |
| **D. 公会** | 社交 + 回城锚点 | 号角购买 → 建会 → 锚点设置/迁移 → 邀请入会 → 一键回公会 → 成员管理 | 20 人上限、锚点最小间距、传送冷却、战斗中禁传全部生效 | B（C 可选） |
| **E. 上线准备** | 过审与包体 | 图集化 + 分包、隐私政策、软著/版号（按品类结论）、提审材料 | 提审通过、包体达标、真机性能达标 | A–D |

**关键判断：阶段 A 完全不依赖服务器。** 所以"后端到底选哪个"这个卡了很久的问题**可以暂时不解决** —— 先把玩法跑起来，别让基础设施问题堵住手感打磨。

## 二、已确认的决策（2026-09-30）

> **7 条全部拍板**，逐条影响清单见 `04-decisions.md`（含"我据此要改什么"与风险）。下表是结论速查；
> 下面保留当时逐条列出的选项对比，**只作背景与备选，不再是待定项**。

| # | 议题 | 结论 |
|---|---|---|
| 1 | 怪与掉落 | **全服共享**；奖励（经验 + 宝箱）归**累计伤害最高**的玩家 —— 抢怪是**设计内行为** |
| 2 | 后端托管 | **抖音云**（⚠️ 长连接与合法域名白名单**仍未验证**，见下） |
| 3 | 首版支付 | **不接**；号角用金币买 |
| 4 | 数值 | 号角 **500 金币**；1 级 → 20 级约 **15 分钟** |
| 5 | 出生与位置 | **首次随机出生 + 之后回上次位置** |
| 6 | 离线收益 | **不做** |
| 7 | 端 | **只做小游戏端**（不写 `web` 平台层） |

**唯一未验证的阻塞项（决策 #2）**：抖音云是否支持 **WebSocket 长连接**、其分配的域名能否进**小游戏合法域名白名单**。
2026-09-30 两次抓官方文档都只拿到 JS 壳（单页应用，正文由脚本渲染），**没有结论**。核对方法见 §三。


### #1（已确认：全服共享 + 按最高伤害结算奖励）

| 方案 | 做法 | 代价 |
|---|---|---|
| A · 全服共享（真 MMO） | 所有人打同一只怪 | 需要伤害归属仲裁、抢怪规则、服务端全量模拟怪 AI；服务器贵、纠纷多 |
| B · 每人一份（个人层）**（未采用）** | 玩家之间**互相可见**，但怪/宝箱/掉落是"我个人的" | 没有抢怪；服务端不用模拟怪；手机本地算，最省 |
| C · 分线（shard） | 按人数切线，线内仍是共享怪 | 介于两者之间，运营复杂 |

> （**未采用**）当时推荐 B 的理由：这套玩法是**纯自动战斗刷宝**，抢怪只制造负面体验；社交感可以由"玩家可见 + 公会锚点可见"提供。
> 最终决定走 **A + 最高伤害者得奖励**：代价（抢怪是设计内行为、服务端成本上升）与两个缓解开关见 `04-decisions.md` #1。

### #2（已确认：抖音云 —— 但长连接与域名白名单仍未验证）

- 阶段 B/C **必须** https/wss + 后台白名单域名。
- **抖音云**：省运维，但需先确认其长连接支持与"默认域名能否直接进小游戏合法域名白名单"（上次调查没拿到结论）。
- **自建**（现有腾讯云 CVM + 已备案域名）：Node + ws + SQLite 是上一版验证过的组合，可控；但备案与证书要自己管。
- **建议**：阶段 A 期间把这一步**并行**查清（只差"域名能否进白名单"一个答案），阶段 B 开始时二选一，不阻塞现在的开发。

### #3（已确认：不接支付，号角用金币买）
- **推荐：不接**。号角用**金币**买，游戏内经济闭环。
- 小游戏内购涉及平台支付政策、商品配置、回调对账、退款流程 —— 单独立项，会显著拉长上线时间。

### #4（已确认：号角 500 金币，20 级约 15 分钟）
- 已确认：号角 `500 金币`（原草案 50,000 金币作废），1→20 级约 **15 分钟**。配套的怪经验/金币产出已在 `01-game-design.md` §6 反推（约 2.5 秒/只 → 350 只怪）。
- ⚠️ 仍需**实机校准**：等阶段 A 用**实测"秒/只"**反算，才是最终数字。另：500 金币意味着"开服当天公会就被建满"，若想要稀缺感建议 `3,000~10,000`。

### #5（已确认：首次随机出生 + 之后回上次位置）
- **推荐**：首次登录随机出生（半径 300~800）；之后回到**上次离线位置**。
- 备选：每次登录都随机出生（更有"无限"感，但会迷路，且公会回城的价值下降）。

### #6（已确认：不做）
- 放置类常见诉求，但**推荐首版不做**：需要服务端按时间差结算掉落，规则复杂，且是外挂重灾区。

### #7（已确认：只做小游戏端，不写 web 层）
- **（未采用）**原推荐：代码一套、两端都能跑，H5 只用于**调试与自动化验证**（不作发行渠道）。最终决定**只做小游戏端**；替代验证方案是"逻辑层纯函数 + node 无头断言 + 游戏内调试面板"，见 `04-decisions.md` #7。

## 四、上一版工程留下的经验（别再踩一遍）

1. **"只有真跑才暴露"的错误**（上一版是 `ACTOR.paths` 写错、静态检查全过但一跑就白屏）→ 所以要**逻辑层无头断言 + 游戏内调试面板 + IDE 真机预览**三道关（决策 #7 不做 web 端，这道的分量更重了）。
2. **常量必须只有一份** → 这一版是 `shared\balance.json`。
3. **无头环境的 FPS / 时间类指标可能是假象**（上一版 `FPS 0`、`MOVEDX=0` 是虚拟时间造成的），别拿它当性能结论。
4. **DOM 与 canvas 事件会互相污染**（上一版引擎在 window 上兜底监听，点 UI 会顺带攻击）→ 这一版自己接管触摸事件。
5. **确定性生成禁止** `Math.random` 与 `Math.sin` 参与哈希：浮点/三角函数在不同引擎可能有细微差异，用 32 位整数哈希 + `Math.imul`。
6. **坐标过网络要整数化**（世界单位 ×10 取整），既省带宽又免抖动。

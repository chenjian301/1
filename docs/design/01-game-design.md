# 玩法设计 · 竖屏无限地图冒险（v1 草案）

> 状态：**草案，等你确认**。本文只写玩法与数值；技术实现见 `02-architecture.md`，阶段划分与未决事项见 `03-roadmap.md`。
> 一句话定位：**竖屏 · 无限地图 · 自动战斗 · 刷宝变强 · 公会据点** —— 主角只负责走位，战斗自动发生。

## 0. 目标平台与硬约束（先看这个，它决定了很多玩法取舍）

| 项 | 值 | 对玩法的影响 |
|---|---|---|
| 载体 | **只做抖音小游戏**（决策 #7：不做 H5 发行版） | 小游戏**没有 DOM**，所有界面必须自绘；因此逻辑层必须与画布/平台彻底分离，才能在服务器上无头断言 |
| 屏幕 | **竖屏**；设计稿宽固定 720，逻辑高度随机型可变 | UI 必须锚点布局（吸顶/吸底），不能写死 y 坐标 |
| 渲染 | 纯 Canvas 2D，无引擎适配层 | 特效要克制：无 shader、无粒子系统，靠贴图 + 加法混合 |
| 网络 | 必须 **https / wss + 后台合法域名白名单** | 账号与联机都依赖它；IP 直连不可行 |
| 玩法基线 | 单人可玩；多人"看得见彼此，但不互相卡" | 先把单机闭环做扎实，再叠云存档与多人 |

## 1. 核心循环

```
出生（随机点） → 走位探索 → 自动打死最近的怪 → 得经验 + 掉宝箱
      ↑                                             ↓
   变得更强 ← 穿戴装备 ← 开箱（六阶） ← 攒宝箱 ← 继续往远处走（怪更强、箱更好）
      ↓
   20 级 → 商城买「号角」→ 建公会 → 设据点锚点 → 公会一键回城
```

**设计意图**：把操作压缩到只剩「移动」（竖屏单手可玩）；把成长做成一条没有上限的线（无限地图 = 无限成长空间）；公会既是社交，也是玩家的**回城锚点**。

│            ▲ 你             │
│        ●蝙蝠                │

├─────────────────────────────┤
│ ▓▓▓▓▓░░░░░░░░░░░░░░░░░░░ │ ← 吸底：经验条（安全区之上，画面最下方）

- **浮动摇杆**：按下才出现，圆心 = 按下点（沿用上一版已验证的手感：模拟量、贴边夹取、死区）。
- **没有攻击键**：攻击是自动的 —— 这是"单手竖屏"的关键取舍。
- **A7 起底部是三层**（从下往上）：**经验条 → 四个技能键 → 六个功能图标**，行距全部由
  `view.hud` 的 `barGap / captionGap / rowGap` 与两个半径推出来；**左下角整块留给浮动摇杆**
  （技能键从屏幕中部下沉到最底、整排靠右，不再压到摇杆区）。
- **`[箱]`** 是"有未开宝箱"的角标，点开进开箱界面。
- **面板**（背包/装备/商城/公会/开箱/设置）都是**卡片式自绘面板** + 关闭键，不是 DOM；
  卡片里的**版面**（角色预览 + 四角装备槽 / 三排背包格 / 属性网格 / 保底条 / 六阶宝箱清单）见 §21.2。

## 3. 无限地图与出生

- 地图**没有边界**，用 `(x, y)` 浮点世界坐标表示，**1 世界单位 = 1 设计像素**（方便和 UI 对齐）。
- **世界种子**：一个赛季一个固定整数（如 `20260930`），写进共用常量 → *同一坐标，所有人看到同一片地*。
- **出生点**：玩家**首次进入**时，在距原点半径 `300~800` 的环形内随机取一点（服务端算，避免所有人叠在原点）；之后登录回到**上次离线位置**（否则每次上线都要重新找路）—— 决策 #5，已确认。
- **原点周围是新手带**，怪最弱、箱最差；越往外越强越好赚 —— 这就是玩家的成长方向，也是"无限地图"的意义所在。

## 4. 移动与自动战斗

| 项 | 规则 |
|---|---|
| 移动 | 只由摇杆驱动；贴图按移动方向换向（八方向素材） |
| 选目标 | 每 `0.1 秒`重算：**全地图距离最近**的可攻击怪（`combat.targetRange = 0` = 不限距离，A7 修订）；同距取 ID 小的（保证确定性） |
| 出手 | 目标进入 `攻击距离` 即按攻速攻击：`间隔 = 1000 / 攻速`（草案 1.6 次/秒） |
| 伤害 | `伤害 = max(1, 攻击力 × (1 + 增伤%) − 目标防御 × 0.6)`；暴击率/暴击伤害为词条 |
| 表现 | 出手播斩击贴图 + 伤害数字飘字；怪有血条；死亡播动画并掉落 |
| 技能（A5） | **四个技能键**：横扫（Lv.1）· 疗愈（Lv.4）· 穿刺（Lv.7）· 旋风（Lv.10）。点一下放，各有自己的冷却，**外加一条 300ms 公共冷却**（防止四个键在同一帧一起炸出去）；自动战斗时**从左到右自动放**（治疗只在血量低于 60% 时放，伤害技要有怪在打击范围内才放） |
| 技能伤害 | 与普攻**同一份公式**，只是把攻击乘上技能的 `damageMul`（决策 #4：公式与数字都只有一处） |
| 不做 | **不做自动寻路**、不做技能连招 —— 技能栏只有四个固定键，**不做技能升级 / 天赋 / 符文** |

> 为什么不做自动寻路：无限地图**没有地形阻挡**（无墙、无碰撞地形），怪会自己来追你。
> 玩家要决策的是"往哪走"，而不是"点哪走"——省掉整条寻路系统。

### 4.1 全服共享怪与奖励归属（决策 #1，已确认）

**怪是全服共享的**：同一只怪、同一份血量，所有玩家看到的是同一只。

| 规则 | 内容 |
|---|---|
| 权威方 | **服务端**：怪的位置、血量、AI、重生、归属全部由服务端裁决；客户端只上报攻击意图并做表现预测 |
| 奖励归属 | 击杀后，**经验 + 宝箱归"对该怪累计伤害最高"的玩家**；其余参与者本次不获得奖励（首版规则，不做分摊） |
| 抢怪 | **是设计内行为**：弱者正在打的怪会被路过的强者抢走奖励 |
| 可见性 | 别人的怪与血条由服务端广播给你（AOI）—— 所以你会看到别人正在打的那只怪 |
| 预留开关 | 代码里留好「首击保护 N 秒」「伤害门槛 ≥ X%」两个开关位置，日后要缓解抢怪时直接打开；**首版均为关闭** |

> 这是一次**有代价的取舍**：换来"大家真在同一片地上打怪"的实感，代价是抢怪纠纷 + 服务端成本。
> 完整影响清单见 `04-decisions.md` #1。


## 5. 怪物与难度分带

- 怪按**距原点的距离**分带（band），每 1000 世界单位一带：

| band | 距离 | 怪等级 | 基础掉箱率 | 高阶箱权重 |
|---|---|---|---|---|
| 0 | 0–1000 | 1–3 | 8% | 基准 |
| 1 | 1000–2000 | 3–6 | 9% | 略升 |
| … | … | … | … | … |
| n | n×1000 起 | 3n ± 2 | 8% + n%（上限 20%） | 随 n 线性上升 |

- **怪的种类首版 4 种**：近战（狼）/ 远程（法师）/ 群怪（蝙蝠）/ 精英（重甲）；每带只换配色与数值，靠 tint 复用贴图。
- **精英怪**：每 chunk 8% 概率生成 1 只；血量 ×5、掉箱率 25%、必出 ≥ 专家箱。
- **重生**：怪死后 `15~30 秒`（确定性伪随机）在同一 chunk 重生；玩家离开该 chunk 超过 2 分钟后其状态丢弃，回来时按规则重生。
- **怪由服务端权威模拟**（决策 #1）：游荡、仇恨、追击、出手、重生全在服务端算，客户端只负责把服务端给的怪画出来。
- **密度上限**：每 chunk 最多 3 只 + 1 只精英 —— 既是玩法节奏，也是服务端 CPU 的护栏（用分帧 tick 摊平 AI 开销）。

## 6. 经验与等级

- **硬指标（决策 #4）：1 级 → 20 级约 15 分钟。**
- 升级所需经验：`need(L) = 150 × L^1.5`（1→20 累计约 10 万经验）。
- 击杀经验：`经验 = (120 + 怪等级 × 60) × (1 + band × 0.15)`；精英 ×5。
  反推依据：自动战斗约 **2.5 秒/只** → 15 分钟约 **350 只** → 单怪平均要给约 **290 经验**（band 0 的 1~3 级怪 = 180~300）。
- 金币产出：`金币 = (4 + 怪等级 × 3) × (1 + band × 0.1)`；精英 ×8 → band 0 每只 **7~13 金币**。
- ⚠️ 以上全部是**估算**：阶段 A 实机跑一次，用**实测的"秒/只"**反算才算校准完成（见 `04-decisions.md` #4）。
- 等级的作用：① **解锁系统（20 级解锁商城与公会）**；② 少量基础属性（每级 +2 攻击、+1% 生命）；③ 装备的等级门槛。
- **不做等级上限、不做死亡惩罚**（无限地图 = 无限成长；首版跑到 60 级左右即可，曲线留足余量）。
- 经验与升级**由服务端结算**（客户端只播升级特效），防改数值。

## 7. 宝箱六阶与掉落

| 阶 | 名称 | 视觉 | 开出装备 | 相对权重（band 0 基准） |
|---|---|---|---|---|
| 1 | 普通 | 木箱 | ≥ 普通 | 8800 |
| 2 | 专家 | 银箱 | ≥ 专家 | 1000 |
| 3 | 史诗 | 金箱 | ≥ 史诗 | 180 |
| 4 | 传说 | 紫箱 | ≥ 传说 | 18 |
| 5 | 神话 | 红箱 | ≥ 神话 | 1.8 |
| 6 | 天赐 | 虹箱 | = 天赐 | 0.2 |

- 掉箱规则：普通怪 `基础掉箱率`（band 0 = 8%，随 band 上升，上限 20%）；精英 25%；**怪不掉装备，只掉箱**（简化叙事与实现）。
- **奖励归属（决策 #1）**：宝箱与经验都给**对该怪累计伤害最高**的玩家，其余参与者这一次什么都拿不到 —— 全服共享怪的完整规则见 §4.1。
- 开箱 = 按箱阶权重抽出**装备等阶**，再生成具体装备（部位、主属性、词条）。
- **保底（pity）**：连续 50 箱未出史诗 → 下一箱强制 ≥ 史诗；连续 500 箱未出神话 → 强制 ≥ 神话。计数存在服务端。
- **概率与开箱必须在服务端**：客户端只发"开这个箱"，播动画用服务端返回的结果（否则改个包就能出神装）。
- **宝箱背包上限 200**：超出自动分解成金币（挂机一整晚也不会爆背包）。
- **背包怎么看**：开箱面板把宝箱背包**按阶汇总**（一阶一行 = 阶名 + × 数量 + 掉落占比，没有的阶也占一行），
  不摆格子 —— 一屏看得全、200 口箱也不会被截断（版面见 §25，取舍见 `README.md` 取舍表第 18 条）。

## 8. 装备系统

- **四个部位**：武器、衣服、鞋子、饰品。
  （2026-09-30 A6 收敛：原先的头盔 / 手套并入"衣服" —— 四个部位各有分工，见 `04-decisions.md` #12）
- **装备目录 60 件**：六阶**各 10 件**，每件写死 **名字 + 部位 + 外观 + 阶内序号**；开箱就是从那一阶的
  10 件里抽一件，再按等阶抽词条。外观（武器造型 / 衣服款式与配色 / 鞋子 / 饰品）**画在角色身上**，
  同一份数据也画成**背包里的内观图标** —— 穿上什么就像什么。

| 阶 | 件数 | 部位分布 | 这一阶的样子 |
|---|---|---|---|
| 普通 → 天赐（6 阶） | 每阶 10 件，共 **60 件** | 武器 3 · 衣服 3 · 鞋 2 · 饰品 2 | 木剑 / 粗布衣 / 草鞋 / 木珠串 → … → 天命之剑 / 天赐圣铠 / 流光仙履 / 天赐星环 |

- 每件装备 = `等阶 + 部位 + 等级门槛 + 主属性 + 0~5 条词条 + 外观`。
- **等级门槛（"装备的等级划分"）= 等阶门槛 + 阶内台阶**：
  `1 + (阶-1) × 3 + floor(阶内序号 / 4)` → 1 阶的 10 件是 **Lv.1~3**，6 阶的 10 件是 **Lv.16~18**（满级 20）。
  **等级不够就穿不上**：开箱的"自动穿上"会跳过它（只进背包），手动点也会被拒并提示还差几级。
- **同阶内越靠后越强**：`statMul = 1 + 阶内序号 × 0.02`（第 10 件 +18%）—— 同阶也有"更好的那一件"。
- 等阶决定**词条数**与**数值倍率**：

| 等阶 | 词条数 | 数值倍率 | 备注 |
|---|---|---|---|
| 普通 | 1 | 1.00 | 过渡 |
| 专家 | 2 | 1.35 | |
| 史诗 | 3 | 1.85 | |
| 传说 | 4 | 2.60 | |
| 神话 | 5 | 3.70 | |
| 天赐 | 5 + 1 条专属特效 | 5.30 | 全服可查掉落记录（稀有性背书） |

- **六阶的发光色（A12，用户：给不同等阶的装备添加发光颜色，分别为白色，蓝色，紫色，金色，红色，炫彩）**：

| 等阶 | 1 普通 | 2 专家 | 3 史诗 | 4 传说 | 5 神话 | 6 天赐 |
|---|---|---|---|---|---|---|
| 阶色（框的描边 / 名字颜色） | 灰 | 绿 | 蓝 | 紫 | 橙 | 金 |
| **发光色（框外那一圈）** | **白** | **蓝** | **紫** | **金** | **红** | **炫彩**（六色轮转） |

  发光色挂在 `balance.equipment.tiers[].glow` 上（末阶是一串颜色 = 炫彩），画法规格在 `balance.view.iconGlow`
  （层数 / 外扩比例 / 呼吸 / 旋色 / 预览光晕）。**有货的格子才发光**：装备格 / 背包格 / 宝箱清单的行图标
  （A13 起，取代原来的箱子格与六阶图例）
  外面描一圈会呼吸的环（越外越淡），空位与等级不够的（`dim`）只描阶色；末阶的炫彩随时间流动；
  背包面板的角色预览在人物背后画一束**身上最高那一阶**的光（光身板就没有）。
  它是**纯表现**：不进数值、不进任何随机流 —— 世界指纹一个字节都没变。

- **主属性按部位分工**：武器 = 攻击、衣服 = 生命、鞋子 = 防御、**饰品 = 暴击率**。
- **词条池**：攻击、生命、防御、攻速、暴击率、暴击伤害、增伤、减伤、经验加成、金币加成、拾取范围……
- **人物属性系统**：「角色属性」面板（设置面板与背包里都有入口）逐项列出 攻击 / 生命上限 / 防御 /
  攻速 / 暴击率 / 暴击伤害 / 增伤 / 减伤 / 移动速度 / 拾取范围 / 经验加成 / 金币加成，
  每一项都写清**"等级基础 + 装备加成"**，玩家一眼知道自己该练级还是该去开箱。
- **战力**：把主属性 + 词条折算成一个单值，用于"穿上会不会更强"的一眼判断（背包里的装备显示 ↑/↓ 箭头）。
- **背包装不下**：一键分解（可按等阶过滤）；掉落直接进包，地面只放一个短促的拾取特效。
- **首版不做**：强化 / 镶嵌 / 重铸 / 洗练 —— 先让"刷到更好的"这一条循环成立，属性改造系统留到 2.0。
  （**2026-10-01 起「强化」已落地**：见 §27 —— 营地里的铁匠 + 商城的强化石，+1 → +10 每级翻倍；
  镶嵌 / 重铸 / 洗练仍然不做。）

## 9. 商城与货币

| 货币 | 来源 | 用途 |
|---|---|---|
| 金币 | 杀怪、分解装备、宝箱溢出 | 号角、传送卷、背包扩容 |
| 钻石 | （后续：任务/活动/付费） | **首版不投放** |

- **20 级解锁商城**；商城首版只卖 3 样：**号角（建公会）**、传送卷（回出生点）、背包扩容。
- **号角价格：`500 金币`（决策 #4）**。按 §6 的金币产出（band 0 每只 7~13 金币）算，**约 50 只怪 / 2 分钟**就能买到 —— 也就是说**开服当天公会就会被建满**。若你希望公会有稀缺感，把价格调到 `3,000~10,000 金币`（15~50 分钟）更合适：这是我唯一建议你再想一下的数字。
- ⚠️ **首版不接真实支付**（号角用金币买）—— 决策 #3，已确认。

## 10. 公会

| 规则 | 值 |
|---|---|
| 解锁 | 角色 ≥ **20 级** 且持有「号角」 |

### 10.1 已经在服务端落地的部分（2026-10-01）

用户要求："创建公会需要自己输入公会名，公会页面显示公会人员，公会等级，公会信息。"
于是公会的**规则与权威都搬到了服务端**（`douyin-cloud\svr\index.js` 的 `/api/guild/*`，六个端点）：

| 端点 | 干什么 | 谁说了算 |
|---|---|---|
| `create` | 用**玩家输入的名字**建会（名字全服唯一）+ 记锚点 | 服务端：重名 409、锚点太近 409 |
| `join` | 用名字加入（人满 409） | 服务端 |
| `leave` | 退会（会长不能退） | 服务端 |
| `anchor` | 会长挪锚点（间距 + 24 小时冷却） | 服务端 |
| `mine` | 我在不在会里 + 整份公会（成员 / 等级 / 锚点） | 服务端**现算**：等级按成员等级之和、在线按"最近 2 分钟跟服务端说过话" |
| `list` | 公会列表（等级 / 人数，按人数降序） | 服务端 |

- 客户端那份（`11-save.js` 的 `G.GUILD`）是**镜像**：`remote:true` 表示服务端真有这条会，
  `teleportAt`（回城冷却）**只在本机**、不上服务端；
- **连不上云时照旧能玩**（决策 #10）：建会在本机成立（`remote:false`），下次能连上时自动**补登记**
  （同一个名字再 create 一次，不重复扣号角）；
- 服务端公会表目前是**内存版**（与存档 / 昵称注册表同一档：重新部署即清）—— 上面那条补登记就是它的自愈。

## 14. 阶段 A4 的变更（2026-09-30，已落地：见 `04-decisions.md` #10）

> 这一节只写**用户可见的规则变化**，不重复实现细节。数值一律还是 `shared/balance.json` 一处。

**界面**

- **面板不再是全屏**：背包 / 商城 / 公会 / 设置 / 营地 都是一张**卡片**（A4 是"约占 1/3 屏面积"；
  2026-10-01 用户把它调高到 **约 2/3 屏高**，见 §23），
  右上角有 ✕，内容超出时在卡片内上下拖动滚动。
- **打开面板时游戏不停止**：世界照旧模拟，玩家照旧能推摇杆走位（卡片外的触摸给摇杆与底部功能键）。
  代价：站着开箱会被怪打 —— 这是玩家自己的选择，取代了 #8d 里"阶段 A 先暂停"的临时方案。
- **右下功能键**从 4 个变 5 个（多了「自动」），站在营地里再多一个「营」；经验条移到**画面最下方**，
  功能键整体抬高让位。
- **左上角**是头像 + 角色名 + 等级（头像由角色名与等级确定，程序自绘）；**玩家头顶**有角色名 + 血条；
  最下方是经验条。

**账号（进游戏之前的三块屏）**

- 标题 → 登录 → 创建角色。登录优先走抖音账号（`tt.login` → 服务端 `code2session` → openid），
  任何一环失败都**降级成本机离线账号**，绝不因为网络问题卡住进游戏。
- 创建角色就是"起个昵称"：2~12 个字符，只允许中文 / 字母 / 数字 / 下划线，保留名不给用。
- **昵称不能重复**是两层：本机注册表（离线立刻给提示，且**改名刷号不释放**旧昵称）+ 服务端 `POST /api/name`
  （跨设备去重）。服务端不可达时降级为仅本机去重，并在界面上写明。

**自动战斗（按钮）**

- 右下「自动」是开关，状态随存档。开启后：**自动走向全地图最近的怪**
  （A7 修订：`combat.targetRange = 0`，不再只看视野内），进攻击距离站住；
  出手本来就是自动的（§4）。
- 摇杆只要推着就**手动优先**，随时可以接管。
- **技能系统仍然不做**（§12 的"不做"清单没变）：自动战斗 = 自动走位 + 自动出手。

**打击感与声音**

- 每次出手有斩击弧线（暴击多四道光刺）；命中**顿帧** 45ms、暴击 110ms、挨打 30ms；
  **震屏只有暴击** 26px/240ms（A7 修订 2 按用户要求"去掉受伤震屏"：挨打**不再抖屏**，
  反馈只留顿帧 + 音效 + 手机震动），两种命中都伴随短震动。
- 音效 8 个 + BGM 1 条，全部由 `tools\gen-minigame-sfx.mjs` **合成**（不引入外部素材）；
  设置面板可以分别关掉音效 / 背景音乐 / 震动，改完立刻生效并存进存档。

**营地（原点）**

- 营地现在是**交互入口**：点底部最左边的「营」可以治疗（按**缺失血量**收金币）、进商城、回营地中心（短冷却、
  战斗中禁用）、回公会锚点。
- **营地是真正的安全区（A6 起）**：巢穴落在**营地半径 900** 内的怪**不装载**（连同它背后那一片都不刷），
  已经在外面的怪一旦闯进半径就被推回边界并转身回家。于是在营地里治疗、看背包、开箱都不会被咬。
  实现上过滤发生在**装载层**（`14-world.loadChunk`），`05-spawn` 的生成流一个字没动 ——
  **世界指纹仍是 `e9802f11`**（跨端确定性建立在生成层）。

## 15. 阶段 A5 的变更（2026-09-30，已落地：见 `04-decisions.md` #11）

> 只写**玩家可见的规则变化**；数值依旧只在 `shared\balance.json`（新增一个 `skills` 块）。

**四个技能键（用户要求"做四个技能栏"）**

- 画面右下、功能键**左侧**多一排**四个技能键**：键面是一个大字，圈下写着技能名。

  | 键 | 名字 | 解锁 | 冷却 | 作用 |
  |---|---|---|---|---|
  | 斩 | 横扫 | Lv.1 | 4 秒 | 打身边 210 范围内的所有怪（1.6 倍攻击） |

## 19. 阶段 A8 的变更（2026-09-30，已落地：见 `04-decisions.md` #16）

**用户标准：一屏 128×128 格（`view.cameraZoom` 0.8 → **0.17578125**）**

- **口径先说清**：竖屏一屏**不可能**是正方形，标准只能落在短边（横向）上。落地后**横向正好 128 格**
  （720 / (0.1758 × 32) = 4096 世界单位），**竖向 = 128 × 手机长宽比**：16:9 → 227 格、
  19.5:9 → **277 格**、20:9 → 284 格、iPad(4:3) → 170 格 —— "两个方向都 ≥ 128 格"成立。
- **代价（实测）**：一格 32 世界单位 × 0.1758 ≈ **2.9 CSS px**（原来 ~13.3）；角色（`player.radius = 24`）
  在 375 宽的屏上约 **4.4 CSS px**。这就是"战略视角"；**把 `view.cameraZoom` 改回 0.8 就回到 A6 的观感**
  （省笔档会自动关掉，一个数即可回退）。
- **随之加的 `view.lodZoom = 0.5`（远距省笔档，没有它这个视野就不成立）**：低于它时一格已不足 ~9 CSS px，
  6 档色 / 每 chunk 40 道细纹 / 装饰全是亚像素噪点 —— 地表**只铺每 chunk 的底色一块**（落笔 7 → 1 次/chunk）、
  **装饰整层跳过**；高于它（如 0.8）一切照旧。

**改动清单**：`shared/balance.json`（`view.cameraZoom`、新增 `view.lodZoom`）· `16-render.js`
（新增纯函数 `groundDetailAt(k)`；`drawGround` / `drawDecor` 走省笔档）· `19-selftest.js`
（旧的"倍率 0.5~1 / 不会小到看不清"下限**被换成新标准本身**：横向正好 128 格 + 省笔档的落笔账，608 → 618 条）· 文档四处。

**账（`tools\perf-frame.mjs`，预算 900 落笔/帧）**：最坏 **684 → 545**，比改前**更低**：

| 场景 | A7 修订 | **A8（128 格 + 省笔档）** |
|---|---|---|
| 野外（怪最多时） | 673 | **545** |
| 站在原点营地里 | 675 | **527** |
| 营地 + 调试面板（最坏） | 684 | **536** |
| 跑到很远的深带 | 659 | **462** |

营地那一帧逐层：地表 + 营地石砖 62 → **168**（视野里的 chunk 从 ~15 涨到 ~162）· 装饰 254 → **0**（省笔档）·
怪 166 · 玩家 27 · 营地道具 + 围栏 52 · 小径路网 2 · 小地图 + HUD 25。
**视野面积涨了 ~20 倍，落笔反而更低** —— 建路径也从 7503 降到 2150。

**已知取舍（诚实的账，任一条都能单独改）**：
1. **怪 / 装饰 / 地标仍只在玩家周围一圈装载**（`view.loadRingChunks = 1` → 3×3 chunk = 1536×1536 世界单位）：
   拉远后这只是屏幕中间的一小块（横向 37% / 纵向 17%），**屏幕其余部分只有地表**。
   要铺满一屏得把装载环开到 9（19×19 = 361 chunk、~700 只怪、落笔 ~8 倍）—— 那是 LOD / 分帧的第二期工作。
2. **小地图不再比屏幕大**：`minimap.chunkRadius = 3` 只覆盖 7×7 chunk = 3584 单位 < 屏幕 4096×8869。
   要恢复"小地图比屏幕广"，把它调到 9（19×19 chunk）。
3. **角色只剩 ~4.4 CSS px**：标准本身的代价（用户明确接受"已知不可玩仍要做"）。
   （**A9 已单独处理这一条：新增演员层 `view.actorMinZoom`，角色 / 怪放大到 A6 同款 ~20 CSS px，见 §20。**）

## 20. 阶段 A9 的变更（2026-09-30，已落地：见 `04-decisions.md` #17）

**用户要求：视角的格子变多了 → 地图的刻画要更细节；还有人物的大小。**

**判断依据（这一版最值钱的一句话）**：一屏 128 格时一格只有 ~2.9 CSS px，
**"把细节画得更细"这条路已经走到头** —— 16×16 色档、每 chunk 40 道细纹、一件一件的装饰，
在这个尺度上全是亚像素噪点。所以 A9 换的是**细节的层级**：同一份地、同一份哈希，
**在大尺度上重画一遍**，让"这里是什么地"看得出来。

**要 1：远距档从"省笔"升级成"宏观地图"**（仍是 `view.lodZoom = 0.5` 那一档）

- **地表：同一片地的粗抽样**。`view.lodGroundBlocks = 4` → 每 chunk 4×4 张色格（一格 128 世界单位
  ≈ **11.7 CSS px**），6 档色照旧；采的是**同一个 `TERRAIN.groundVariant` 色场**，只是隔点取样 ——
  远看与近看是同一片地。亮暗差比近景略大（0.09 vs 0.07），11.7 px 的格子才看得出纹理。
- **装饰：聚合成宏观斑**（新增纯函数 `TERRAIN.decorBlobs`）。它按 `buildChunkDecor` **完全相同的
  调用顺序**跑同一条随机流（不建对象、只累加），按种类算质心与散布，返回 ≤ `view.lodDecorBlobs = 2` 个斑
  （草甸 / 石滩 / 林地，半径 48~150 世界单位 ≈ 4~14 CSS px）。**"远看那片林子"就是"走过去看到的那片林子"** ——
  聚合是抽样，不是另画一套示意（自检里断言主种类与质心逐位一致）。
- **落笔反而更少**：粗色格按同 band（同主题同色偏）的调色板槽攒路径，每槽每档一次 `fill`。
  一屏 171 个 chunk 的地表 **89 笔**（原来"每 chunk 一次 fillRect"是 171 笔）。
  硬不变量：落笔 ≤ 槽数 ×（6 档 + 3 种斑）。

**要 2：演员层最小观感尺寸**（新增 `view.actorMinZoom = 0.8`）

- **只放大点状的东西**：角色与怪的身体 / 影子、仇恨圈、精英圈与王冠、目标环、弹道、近战刀光 ——
  按 `actorMinZoom / zoom`（当前 **4.55 倍**）绕各自的位置反向放大。
- **面状的一律不动**（世界尺寸）：地表 / 路 / 营地 / 地标 / 技能 AoE 环 —— 放大它们就是显示"假的范围"。
- **文字与血条仍是设计像素**，只有**抬升量**跟着放大（否则会被放大后的身体盖住）；
  **攻击范围环在宏观档不画**（世界比例下只剩 ~8 CSS px，只会被身体盖住）。
- 效果：角色 **4.39 → 20.00 CSS px**（= A6 时代的大小），一格仍是 2.93 CSS px。
- 代价（有意接受）：世界被压缩 4.55 倍而角色没有 → "角色看起来比脚下的地大"、贴身战斗会重叠。
  一个数回退：`actorMinZoom = 0`。

**账（预算 900 落笔/帧）**：最坏 **545 → 450**；营地那一帧地表 + 石砖 **168 → 56**、装饰 254 → **0**
（由宏观斑代替）；建路径 2150 → 5063（"地表有纹理"的代价）。

**尺子**：`tools\view-metrics.mjs` 现在会打"粗色格 / 斑 / 角色（含演员层）各几 CSS px"，
并印一张**宏观地形文本预览**（每字符 = 一个粗色格；0..5 = 色档、g / r / T = 草甸 / 石滩 / 林地）——
不跑 IDE 也能看出地表有没有结构。

## 22. 阶段 A11 的变更（2026-09-30，已落地：见 `04-decisions.md` #19）

**用户要求：地图、相机视角还需要优化 —— 需要让地图更加细节，玩家视角更加清晰。**

**判断依据（这一版最值钱的一句话）**：细节与视野是**一对取舍**，而且是乘法关系：
`一格在屏幕上几 CSS px = world.tileSize × zoom × (cssW / designWidth)`。
A8 的「一屏 128 格」= 一格 **2.93 CSS px** —— 在这个尺度上"把地画得更细"没有意义（全是亚像素噪点），
A9 的宏观档已经是那条路的尽头。所以 A11 不再硬抠一个数，而是**把选择交给玩家**，并把代价写在提示里。

### 22.1 三个视角档位（`view.cameraTiers`）

| 档 | 一屏横向 | zoom | 一格 CSS px | 地表 | 装载环 | 一句话 |
|---|---|---|---|---|---|---|
| 远 | 128 格 | 0.176 | 2.93 | 宏观：4 格一色格（11.7 CSS px） | 1 | A8 的战略视角：看路网与地标，不看脚下 |
| 中 | 64 格 | 0.352 | 5.86 | 宏观：逐格采样（5.9 CSS px） | 2 | 看得清脚下每一格，也看得到小半个营地 |
| 近 | 32 格 | 0.703 | 11.72 | 逐格档：16×16 色格 + 细纹 + 逐件装饰 | 2 | 全保真：一草一木都是真模型 |

- **默认视角不是任何一档（A11 之三，用户："默认格子数量设置为 22"）**：新号开机是**一屏 22 格**
  （`view.zoomTiles = 22`、`cameraTier` 启动档 = 近）：一格 **17.05 CSS px**、视野 **22×29 格**、
  角色（按世界尺寸画，演员层不生效）直径 **25.6 CSS px**、小地图 1 chunk。
  它比 1:1 略近一点（**一屏 22.5 格才是 1:1**），也不落在任何预设档位上 —— 所以档名如实显示「自定义」，
  而宏观色格 / 装载环 / 小地图半径取**最近的那一档**（近档）。
- **怎么切（A11 之二起是"拖"）**：设置面板里那一行**视角缩放滚动轴**（`view.zoomSlider`，一屏 **16 ~ 64 格**，
  按下即跳到手指位置、拖动时世界跟着缩放、**松手才写存档**），**写进存档**（`settings.zoomTiles` + `settings.zoomTier`，重开还记得），
  并给一句带数字的提示（"视角：一屏 22 格（一格 17.05 CSS px）"）；调试面板也常显这一行。
  > 更正：A11 当时文档里写的"设置面板一行「视角」（点一下换下一档）"**并没有真的做出来**
  > （只有 handler，没有行），玩家真正能改视角的入口是 A11 之二补上的滑块 —— 见 §22.6 与 `04-decisions.md` #21。
- **每档一个色格边长**（`lodBlockTiles`）：远 4 格 / 中 1 格 —— 同一片地，中档每 5.9 CSS px 换一次色、
  远档每 11.7 CSS px 换一次，**拉近一档 = 地表看得见的斑驳细一倍**（不是"格子跟着放大"）。
- **宏观调色板往主题主色收 45%**（`view.lodBlend`）：色格变小之后若每格都用满对比的原色，远看就是
  一张噪声马赛克；收一收就变成"同一片地、带淡淡斑驳"的纹理。**结构**交给装饰斑（三种斑都描了轮廓）
  与路网 —— 那是世界数据里**真实存在**的中等尺度结构（同一随机流聚合出来的，见 A9）。
- **装载环跟着档位走**（`cameraTiers[].loadRing`）：近档 2 圈就能把整屏填满（装饰与怪都看得见），
  中档 2 圈覆盖屏幕中部，远档保持 1 圈（视野是 8×17 个 chunk，再大装不下，见 §22.5）。
  另外：**地表的绘制范围与装载无关**（`CHUNK.chunksInRect(viewRect)`，纯哈希）—— 所以任何档位下
  "一整屏都有地"，只是"有装饰、有怪"的范围受装载环限制。

### 22.2 相机：锁定以角色为中心 + 归位

**A11 之三（用户："视角没有锁定以角色为中心"）把 A11 的前瞻偏移关掉了**。
- **锁定**：`view.cameraLerpPerTick = 1` —— 每逻辑帧直接把相机放到"玩家 + 前瞻"上，
  角色因此**恒画在屏幕正中**（`toScreen(相机, 玩家坐标)` 正好等于屏幕中心，自检断言这一条）。
  1 是"锁定"、小于 1 是"缓动跟随"（镜头落后一点点），这个数留在 balance 里就是那个开关。
- **前瞻已关**：`view.cameraLookAhead = 0`。A11 原本让镜头往"正在走的方向 / 正在打的目标"前移 240 世界单位
  （屏幕正中 = "我 + 我要去的地方"）；但那个偏移以**世界单位**计，视角越近占屏幕的比例越大 ——
  默认 22 格时占半屏 **34%**、滑到 16 格时 **47%**，角色会被挤到屏幕边上。用户要的是锁定，所以关掉
  （机制留着：把数改成非 0 就恢复；自检按"≤ 0 就是关"验）。
- **纯表现**：只改渲染用的相机，**逻辑层读到的玩家坐标一个字节都没变**（自检断言这一条）。
- **归位**：传送（公会 / 营地）、复活、读档、换档、拖缩放轴都会走 `snapCamera()`，
  否则镜头会带着上一处的偏移"飘"过去。

### 22.3 玩家视角更清晰的三处小东西

1. **玩家标记**（`view.playerMark`）：脚下常亮的一圈金色细环（+ 很轻的呼吸感），
   **屏幕尺寸恒定**（不随档位变）—— 任何档位都一眼找得到"我"。它是指示物不是范围（与名牌同一条纪律）。
2. **小地图跟着档位放大**：半径 = 装得下整屏所需的最小 chunk 半径（远 9 / 中 5 / 近 3）。
   A8 那个"小地图比屏幕小"的待办在这一版修掉了 —— 屏幕多大，地图就多大。
3. **小地图上的视野框**：主画面覆盖的那一块画成一根细框（以**相机**为中心；A11 之三起相机 = 角色，
   所以框也跟着角色走）："我屏幕上看到的，就是地图上这一块"。

### 22.5 已知取舍（诚实的账）

1. **远档的屏幕外圈没有"逐件的装饰与怪"**：视野是 8×17 个 chunk，装载环 1 圈（3×3）——
   再往外只有地表、宏观斑与路网。要铺满得把环开到 9（19×19 = 361 chunk、~700 只怪），
   落笔会接近预算上限，所以这一条留给用户拍板（A8 起就挂在取舍清单上）。
2. **世界数据本身只有三层尺度**：每档主题（大）、每 chunk 的装饰（中，且是哈希噪声）、每格色（细）。
   所以"远看出现河流 / 山谷"那种结构**做不到** —— 那属于**生成层**的改动（会换掉世界指纹 `e9802f11`，
   还要同步 TypeScript 侧）。A11 做的是把**已有的**细节按档位分层展示，并让玩家自己选。
3. **换档会瞬移观感**（不是平滑拉镜头）：拉近一档 = 视野面积小 4 倍。做成平滑缩放需要新的动画状态与
   更贵的一帧（缩放期间所有世界元素都要重画），第一版不做。
4. **三档里近档最贵**（552/900）：如果某台机器上感觉卡，切到中档即可（~372）。
   滑块（§22.6）最贵的一格是 **45 格（658/900）**，也在预算内。
5. **相机锁定以角色为中心之后，"前进方向"重新变成盲区**（A11 之三，按用户要求）：
   屏幕正中是我，不是"我要去的地方" —— A11 的前瞻偏移（240 世界单位）因此关掉。
   为什么仍然值得：那个偏移以**世界单位**计，近距离视角下占屏幕的比例大到会把角色挤到边上
   （默认 22 格时占半屏 34%、16 格时 47%）。白捡的一笔：视野矩形不再偏向一侧，**落笔普遍降了一截**
   （§22.4 的 703 → 658）。想恢复就把 `view.cameraLookAhead` 改回非 0。

### 22.6 视角缩放滚动轴（A11 之二：`view.zoomSlider` + `view.zoomTiles`）

**用户要求：玩家设置中添加视角缩放滚动轴，可以缩到 16-64。**

> 顺带更正一件事：A11 文档里写的"设置面板一行「视角」"**当时并没有真的做出来**
> （`handleAction` 有 `zoomNext` 分支，但没有任何一行产出它）—— 所以这一版是**第一次**给玩家
> 一个真的能改视角的入口，而不是把点按改成拖动。

- **一个数说了算**：`view.zoomTiles` = 一屏横向多少格，`zoom = designWidth / (zoomTiles × world.tileSize)`。
  落在预设档位上（`zoomTiles` == 那一档的 `tiles`）时**直接用表里的 zoom** —— 128 / 64 / 32 因此永远是精确数；
  拖到两档之间才现算，档名显示「自定义」（档名不再等于倍率时写"中"就是在骗玩家）。
- **档位仍在，身份变了**：`view.cameraTier` 现在记的是"**最近的档**" —— 宏观色格边长 / 装载环 / 小地图半径
  都挂在档位上，于是拖滑块时这些"档"级别的规格不会每拖一下乱跳（拖到 40 格 = 按近档画）。
- **范围与画法都在 balance**：`view.zoomSlider = { minTiles: 16, maxTiles: 64, trackHeight: 22, knobRadius: 20, endPad: 26 }`。
  下限同时是**硬下限**（再近一屏装不下 2×2 个 chunk，怪会贴到脸上）；**上限只限制滑块** ——
  远档 128 仍由 `cameraTiers` 提供（本版没有界面入口，想放开就改这一个数）。
- **手感**：按下立刻跳到手指位置（点轨道 = 跳到那一点）、左右拖 = 改格数、**拖动不吃滚动**（卡片内容不跟着跑）、
  拖动过程**世界边拖边缩放**（静默，不写存储）、**松手才落盘**（外加一句带数字的提示）。
- **默认值（A11 之三，用户："默认格子数量设置为 22"）**：`view.zoomTiles = 22`、`view.cameraTier = 2`（近档，
  离 22 最近的那一档）。`setZoomTiles` 顺手把存档里的 `settings.zoomTier` 也写成最近的档 ——
  两个字段因此**永远自洽**（不会一个说"中"一个说 22 格），自检断言这一条。
- **账（`tools\view-metrics.mjs` 与 `tools\perf-frame.mjs` 各新增一节）**：

| 一屏 | zoom | 一格 | 地表细节档 | 角色（含演员层） | 小地图 | 最贵一帧（预算 900） |
|---|---|---|---|---|---|---|
| 16 格 | 1.406 | 23.44 CSS px | 逐格档 | 35 CSS px | 1 chunk | 505 |
| **22 格（默认）** | **1.0227** | **17.05 CSS px** | **逐格档** | **25.6 CSS px（演员层不生效：倍率已高于 0.8）** | **1** | **519** |
| 40 格 | 0.5625 | 9.38 CSS px | 逐格档 | 20 CSS px（演员层下限刚好生效） | 2 | — |
| 45 格 | 0.5 | 8.33 CSS px | 逐格档（正好等于阈值） | 20 CSS px | 2 | **658** |
| 64 格 | 0.3516 | 5.86 CSS px | 宏观档 | 20 CSS px | 3 | 384 |

- ⚠ **45 → 46 格会换档**：阈值 `view.lodZoom = 0.5` 是 A8 就有的，滑块只是让它变成"手能拖到"的位置 ——
  往右拖一格，地表从 16×16 色块 + 细纹 + 逐件装饰变成 1 格色块 + 装饰斑（落笔 658 → ~380，画面明显变"糊"）。
- ⚠ **按整格走**：一屏 16..64 格 = 49 个位置，读数与存档都是整数；代价是 0.8 这种倍率拖不出来（要 28.125 格）。

## 24. 阶段 A12 的变更（2026-10-01，已落地：见 `04-decisions.md` #23）

**需求（用户原话）**："给不同等阶的装备添加发光颜色，分别为白色，蓝色，紫色，金色，红色，炫彩"。

### 24.1 六阶的发光色（一份数据）

颜色挂在 `balance.equipment.tiers[].glow` 上（数组 —— 末阶是一串六个颜色 = 炫彩），
画法规格在 `balance.view.iconGlow`（`layers` / `spreadRatio` / `lineWidth` / `alpha` /
`pulseMs` + `pulseAmp` / `spinMs` / `haloRadiusMul` + `haloLayers` + `haloAlpha`）。
**阶色与发光色是两件事**：框的描边与名字仍然用 `TIER_COLORS`（A6 定的灰 / 绿 / 蓝 / 紫 / 橙 / 金），
新加的是框**外面那一圈**（白 / 蓝 / 紫 / 金 / 红 / 炫彩）—— 于是"我是哪一阶"与"这一阶有多亮"分开读。

### 24.2 画法（`16-icons.js` 的 `glowRing` / `heroGlow`）

- **发光 = 多层描边**（假 canvas 没有 `shadowBlur`，与地表石碑 / 营地火光同一套画法）：沿同一个八角框
  往外画 `layers` 层、**越外越淡**，每层再乘一个**呼吸系数**；
- **呼吸用三角波**（`glowPulse`）：面板开着时每帧都要重画，而 `16-icons.js` 从 A6 起就是 **trig-free**
  的（`check-minigame.ps1` 的三角函数白名单里没有它），所以用 `1 - |2t/T - 1|` 而不是 `sin`/`cos`；
- **炫彩 = 层与层错开一位 + 每 `spinMs` 换一格**（`glowColorAt`）：三层同时挂三种颜色，看着像在流动；
- **`frame()` 多一个 `phase` 参数，且只有"有货"的格子才发光**（`dim !== true`）——
  空位与等级不够的仍然只描阶色：它们是占位，不是货；
- **时间基准由调用方给**（`18-panels.js` 的 `glowPhase()` = `WORLD.now()`）：跟游戏一起走、一起停，
  不碰 `Date.now`（那是 12-platform / 20-main 的活），而且 `glowPulse` / `glowColorAt` 是**纯函数**，
  自检能逐点断言（周期首尾相接、夹在 `[1-pulseAmp, 1]`、炫彩一个 `spinMs` 后换色）。

### 24.3 发光出现在哪几处（A12 时是四处；A13 把"箱子格 + 图例"并成一处清单，见 §25）

| 位置 | 画法 | 为什么 |
|---|---|---|

### 27.4 强化规则（全部在 `balance.enhance` 一处）

| 等级 | 这一级要几颗 | 累计 | 主属性加成 | 升这一级要的金币（按 100 金币/颗） |
|---|---|---|---|---|
| +1 | 1 | 1 | +10% | 100 |
| +2 | 2 | 3 | +20% | 200 |
| +3 | 4 | 7 | +30% | 400 |
| +4 | 8 | 15 | +40% | 800 |
| +5 | 16 | 31 | +50% | 1,600 |
| +6 | 32 | 63 | +60% | 3,200 |
| +7 | 64 | 127 | +70% | 6,400 |
| +8 | 128 | 255 | +80% | 12,800 |
| +9 | 256 | 511 | +90% | 25,600 |
| +10 | 512 | **1023** | **+100%（翻倍）** | 51,200 |

- **公式**：成本 = `baseStones × growth^当前等级`（1 / 2 / 4 / … / 512）；**每级翻倍**是用户给的口径
  （"+1 一个、+2 两个、+3 四个，依此类推"）。一把武器从 +0 敲到 +10 一共 **1023 颗石头 = 102,300 金币** ——
  这是**长期目标**的价位（按 §6 的产出，band 0 一只怪 7~13 金币），不是开服第一天能敲满的；
- **加成加在主属性上**（攻击 / 生命 / 防御 / 暴击率），词条是掉落那一刻抽死的、铁匠**不动它们**；
  战力按同一条公式重算，所以背包里的 ↑↓ 与铁匠面板里的"战力 100 → 112"是同一把尺子；
- **等级存在装备自己身上**（`item.enhance`）：它跟着这件装备走（卖了就没了、换一件就是另一套等级、
  脱下来再穿回去还是 +10）。老存档没有这个字段 = 0 级，**不用升存档版本号**；
- **坏数据一律拦住**：缺字段 / 字符串 / NaN / 负数 → 0 级，`+999` → 夹到上限（读档时就跑一遍）。

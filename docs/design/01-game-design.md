# 玩法设计 · 竖屏无限地图冒险（v1 草案）

> 状态：**草案，等你确认**。本文只写玩法与数值；技术实现见 `02-architecture.md`，阶段划分与未决事项见 `03-roadmap.md`。
> 一句话定位：**竖屏 · 无限地图 · 自动战斗 · 刷宝变强 · 公会据点** —— 主角只负责走位，战斗自动发生。

## 0. 目标平台与硬约束（先看这个，它决定了很多玩法取舍）

| 项 | 值 | 对玩法的影响 |
|---|---|---|
| 载体 | **只做抖音小游戏**（决策 #7：不做 H5 发行版） | 小游戏**没有 DOM**，所有界面必须自绘；因此逻辑层必须与画布/平台彻底分离，才能在服务器上无头断言 |
| 屏幕 | **竖屏**；设计稿宽固定 720，逻辑高度随机型可变 | UI 必须锚点布局（吸顶/吸底），不能写死 y 坐标 |
| 渲染 | 纯 Canvas 2D，无引擎适配层 | 特效要克制：无 shader、无粒子系统，靠贴图 + 加法混合 |
| 网络 | 必须 **https / wss + 后台合法域名白名单** | 账号与联机都依赖它；IP 直连不可行 |
| 玩法基线 | 单人可玩；多人"看得见彼此，但不互相卡" | 先把单机闭环做扎实，再叠云存档与多人 |

## 1. 核心循环

```
出生（随机点） → 走位探索 → 自动打死最近的怪 → 得经验 + 掉宝箱
      ↑                                             ↓
   变得更强 ← 穿戴装备 ← 开箱（六阶） ← 攒宝箱 ← 继续往远处走（怪更强、箱更好）
      ↓
   20 级 → 商城买「号角」→ 建公会 → 设据点锚点 → 公会一键回城
```

**设计意图**：把操作压缩到只剩「移动」（竖屏单手可玩）；把成长做成一条没有上限的线（无限地图 = 无限成长空间）；公会既是社交，也是玩家的**回城锚点**。

## 2. 竖屏界面布局

```
┌─────────────────────────────┐ 设计宽 720（固定），逻辑高 = 屏幕高 / 缩放
│ Lv.12  ▓▓▓▓▓░░░░  1.2k/2.4k │ ← 吸顶：等级 + 经验条
│ 🪙 12,340   💎 0      ⛨  🎒  │ ← 吸顶右：货币 + 公会/背包按钮
├─────────────────────────────┤
│                             │
│        （世界视野）          │ ← 相机居中的无限地图；自动战斗就发生在这里
│     ●狼        ●骷髅        │
│            ▲ 你             │
│        ●蝙蝠                │
│                             │
├─────────────────────────────┤
│  ◉摇杆          [回公会] [箱]│ ← 吸底：浮动摇杆（左）+ 功能键（右）
└─────────────────────────────┘ 安全区：底部预留约 120 逻辑像素
```

- **浮动摇杆**：按下才出现，圆心 = 按下点（沿用上一版已验证的手感：模拟量、贴边夹取、死区）。
- **没有攻击键**：攻击是自动的 —— 这是"单手竖屏"的关键取舍。
- **`[箱]`** 是"有未开宝箱"的角标，点开进开箱界面。
- **面板**（背包/装备/商城/公会/开箱/设置）都是**全屏自绘面板** + 返回键，不是 DOM。

## 3. 无限地图与出生

- 地图**没有边界**，用 `(x, y)` 浮点世界坐标表示，**1 世界单位 = 1 设计像素**（方便和 UI 对齐）。
- **世界种子**：一个赛季一个固定整数（如 `20260930`），写进共用常量 → *同一坐标，所有人看到同一片地*。
- **出生点**：玩家**首次进入**时，在距原点半径 `300~800` 的环形内随机取一点（服务端算，避免所有人叠在原点）；之后登录回到**上次离线位置**（否则每次上线都要重新找路）—— 决策 #5，已确认。
- **原点周围是新手带**，怪最弱、箱最差；越往外越强越好赚 —— 这就是玩家的成长方向，也是"无限地图"的意义所在。

## 4. 移动与自动战斗

| 项 | 规则 |
|---|---|
| 移动 | 只由摇杆驱动；贴图按移动方向换向（八方向素材） |
| 选目标 | 每 `0.1 秒`重算：**视野内距离最近**的可攻击怪；同距取 ID 小的（保证确定性） |
| 出手 | 目标进入 `攻击距离` 即按攻速攻击：`间隔 = 1000 / 攻速`（草案 1.6 次/秒） |
| 伤害 | `伤害 = max(1, 攻击力 × (1 + 增伤%) − 目标防御 × 0.6)`；暴击率/暴击伤害为词条 |
| 表现 | 出手播斩击贴图 + 伤害数字飘字；怪有血条；死亡播动画并掉落 |
| 技能（A5） | **四个技能键**：横扫（Lv.1）· 疗愈（Lv.4）· 穿刺（Lv.7）· 旋风（Lv.10）。点一下放，各有自己的冷却，**外加一条 300ms 公共冷却**（防止四个键在同一帧一起炸出去）；自动战斗时**从左到右自动放**（治疗只在血量低于 60% 时放，伤害技要有怪在打击范围内才放） |
| 技能伤害 | 与普攻**同一份公式**，只是把攻击乘上技能的 `damageMul`（决策 #4：公式与数字都只有一处） |
| 不做 | **不做自动寻路**、不做技能连招 —— 技能栏只有四个固定键，**不做技能升级 / 天赋 / 符文** |

> 为什么不做自动寻路：无限地图**没有地形阻挡**（无墙、无碰撞地形），怪会自己来追你。
> 玩家要决策的是"往哪走"，而不是"点哪走"——省掉整条寻路系统。

### 4.1 全服共享怪与奖励归属（决策 #1，已确认）

**怪是全服共享的**：同一只怪、同一份血量，所有玩家看到的是同一只。

| 规则 | 内容 |
|---|---|
| 权威方 | **服务端**：怪的位置、血量、AI、重生、归属全部由服务端裁决；客户端只上报攻击意图并做表现预测 |
| 奖励归属 | 击杀后，**经验 + 宝箱归"对该怪累计伤害最高"的玩家**；其余参与者本次不获得奖励（首版规则，不做分摊） |
| 抢怪 | **是设计内行为**：弱者正在打的怪会被路过的强者抢走奖励 |
| 可见性 | 别人的怪与血条由服务端广播给你（AOI）—— 所以你会看到别人正在打的那只怪 |
| 预留开关 | 代码里留好「首击保护 N 秒」「伤害门槛 ≥ X%」两个开关位置，日后要缓解抢怪时直接打开；**首版均为关闭** |

> 这是一次**有代价的取舍**：换来"大家真在同一片地上打怪"的实感，代价是抢怪纠纷 + 服务端成本。
> 完整影响清单见 `04-decisions.md` #1。


## 5. 怪物与难度分带

- 怪按**距原点的距离**分带（band），每 1000 世界单位一带：

| band | 距离 | 怪等级 | 基础掉箱率 | 高阶箱权重 |
|---|---|---|---|---|
| 0 | 0–1000 | 1–3 | 8% | 基准 |
| 1 | 1000–2000 | 3–6 | 9% | 略升 |
| … | … | … | … | … |
| n | n×1000 起 | 3n ± 2 | 8% + n%（上限 20%） | 随 n 线性上升 |

- **怪的种类首版 4 种**：近战（狼）/ 远程（法师）/ 群怪（蝙蝠）/ 精英（重甲）；每带只换配色与数值，靠 tint 复用贴图。
- **精英怪**：每 chunk 8% 概率生成 1 只；血量 ×5、掉箱率 25%、必出 ≥ 专家箱。
- **重生**：怪死后 `15~30 秒`（确定性伪随机）在同一 chunk 重生；玩家离开该 chunk 超过 2 分钟后其状态丢弃，回来时按规则重生。
- **怪由服务端权威模拟**（决策 #1）：游荡、仇恨、追击、出手、重生全在服务端算，客户端只负责把服务端给的怪画出来。
- **密度上限**：每 chunk 最多 3 只 + 1 只精英 —— 既是玩法节奏，也是服务端 CPU 的护栏（用分帧 tick 摊平 AI 开销）。

## 6. 经验与等级

- **硬指标（决策 #4）：1 级 → 20 级约 15 分钟。**
- 升级所需经验：`need(L) = 150 × L^1.5`（1→20 累计约 10 万经验）。
- 击杀经验：`经验 = (120 + 怪等级 × 60) × (1 + band × 0.15)`；精英 ×5。
  反推依据：自动战斗约 **2.5 秒/只** → 15 分钟约 **350 只** → 单怪平均要给约 **290 经验**（band 0 的 1~3 级怪 = 180~300）。
- 金币产出：`金币 = (4 + 怪等级 × 3) × (1 + band × 0.1)`；精英 ×8 → band 0 每只 **7~13 金币**。
- ⚠️ 以上全部是**估算**：阶段 A 实机跑一次，用**实测的"秒/只"**反算才算校准完成（见 `04-decisions.md` #4）。
- 等级的作用：① **解锁系统（20 级解锁商城与公会）**；② 少量基础属性（每级 +2 攻击、+1% 生命）；③ 装备的等级门槛。
- **不做等级上限、不做死亡惩罚**（无限地图 = 无限成长；首版跑到 60 级左右即可，曲线留足余量）。
- 经验与升级**由服务端结算**（客户端只播升级特效），防改数值。

## 7. 宝箱六阶与掉落

| 阶 | 名称 | 视觉 | 开出装备 | 相对权重（band 0 基准） |
|---|---|---|---|---|
| 1 | 普通 | 木箱 | ≥ 普通 | 8800 |
| 2 | 专家 | 银箱 | ≥ 专家 | 1000 |
| 3 | 史诗 | 金箱 | ≥ 史诗 | 180 |
| 4 | 传说 | 紫箱 | ≥ 传说 | 18 |
| 5 | 神话 | 红箱 | ≥ 神话 | 1.8 |
| 6 | 天赐 | 虹箱 | = 天赐 | 0.2 |

- 掉箱规则：普通怪 `基础掉箱率`（band 0 = 8%，随 band 上升，上限 20%）；精英 25%；**怪不掉装备，只掉箱**（简化叙事与实现）。
- **奖励归属（决策 #1）**：宝箱与经验都给**对该怪累计伤害最高**的玩家，其余参与者这一次什么都拿不到 —— 全服共享怪的完整规则见 §4.1。
- 开箱 = 按箱阶权重抽出**装备等阶**，再生成具体装备（部位、主属性、词条）。
- **保底（pity）**：连续 50 箱未出史诗 → 下一箱强制 ≥ 史诗；连续 500 箱未出神话 → 强制 ≥ 神话。计数存在服务端。
- **概率与开箱必须在服务端**：客户端只发"开这个箱"，播动画用服务端返回的结果（否则改个包就能出神装）。
- **宝箱背包上限 200**：超出自动分解成金币（挂机一整晚也不会爆背包）。

## 8. 装备系统

- **四个部位**：武器、衣服、鞋子、饰品。
  （2026-09-30 A6 收敛：原先的头盔 / 手套并入"衣服" —— 四个部位各有分工，见 `04-decisions.md` #12）
- **装备目录 60 件**：六阶**各 10 件**，每件写死 **名字 + 部位 + 外观 + 阶内序号**；开箱就是从那一阶的
  10 件里抽一件，再按等阶抽词条。外观（武器造型 / 衣服款式与配色 / 鞋子 / 饰品）**画在角色身上**，
  同一份数据也画成**背包里的内观图标** —— 穿上什么就像什么。

| 阶 | 件数 | 部位分布 | 这一阶的样子 |
|---|---|---|---|
| 普通 → 天赐（6 阶） | 每阶 10 件，共 **60 件** | 武器 3 · 衣服 3 · 鞋 2 · 饰品 2 | 木剑 / 粗布衣 / 草鞋 / 木珠串 → … → 天命之剑 / 天赐圣铠 / 流光仙履 / 天赐星环 |

- 每件装备 = `等阶 + 部位 + 等级门槛 + 主属性 + 0~5 条词条 + 外观`。
- **等级门槛（"装备的等级划分"）= 等阶门槛 + 阶内台阶**：
  `1 + (阶-1) × 3 + floor(阶内序号 / 4)` → 1 阶的 10 件是 **Lv.1~3**，6 阶的 10 件是 **Lv.16~18**（满级 20）。
  **等级不够就穿不上**：开箱的"自动穿上"会跳过它（只进背包），手动点也会被拒并提示还差几级。
- **同阶内越靠后越强**：`statMul = 1 + 阶内序号 × 0.02`（第 10 件 +18%）—— 同阶也有"更好的那一件"。
- 等阶决定**词条数**与**数值倍率**：

| 等阶 | 词条数 | 数值倍率 | 备注 |
|---|---|---|---|
| 普通 | 1 | 1.00 | 过渡 |
| 专家 | 2 | 1.35 | |
| 史诗 | 3 | 1.85 | |
| 传说 | 4 | 2.60 | |
| 神话 | 5 | 3.70 | |
| 天赐 | 5 + 1 条专属特效 | 5.30 | 全服可查掉落记录（稀有性背书） |

- **主属性按部位分工**：武器 = 攻击、衣服 = 生命、鞋子 = 防御、**饰品 = 暴击率**。
- **词条池**：攻击、生命、防御、攻速、暴击率、暴击伤害、增伤、减伤、经验加成、金币加成、拾取范围……
- **人物属性系统**：「角色属性」面板（设置面板与背包里都有入口）逐项列出 攻击 / 生命上限 / 防御 /
  攻速 / 暴击率 / 暴击伤害 / 增伤 / 减伤 / 移动速度 / 拾取范围 / 经验加成 / 金币加成，
  每一项都写清**"等级基础 + 装备加成"**，玩家一眼知道自己该练级还是该去开箱。
- **战力**：把主属性 + 词条折算成一个单值，用于"穿上会不会更强"的一眼判断（背包里的装备显示 ↑/↓ 箭头）。
- **背包装不下**：一键分解（可按等阶过滤）；掉落直接进包，地面只放一个短促的拾取特效。
- **首版不做**：强化 / 镶嵌 / 重铸 / 洗练 —— 先让"刷到更好的"这一条循环成立，属性改造系统留到 2.0。

## 9. 商城与货币

| 货币 | 来源 | 用途 |
|---|---|---|
| 金币 | 杀怪、分解装备、宝箱溢出 | 号角、传送卷、背包扩容 |
| 钻石 | （后续：任务/活动/付费） | **首版不投放** |

- **20 级解锁商城**；商城首版只卖 3 样：**号角（建公会）**、传送卷（回出生点）、背包扩容。
- **号角价格：`500 金币`（决策 #4）**。按 §6 的金币产出（band 0 每只 7~13 金币）算，**约 50 只怪 / 2 分钟**就能买到 —— 也就是说**开服当天公会就会被建满**。若你希望公会有稀缺感，把价格调到 `3,000~10,000 金币`（15~50 分钟）更合适：这是我唯一建议你再想一下的数字。
- ⚠️ **首版不接真实支付**（号角用金币买）—— 决策 #3，已确认。

## 10. 公会

| 规则 | 值 |
|---|---|
| 解锁 | 角色 ≥ **20 级** 且持有「号角」 |
| 创建 | 消耗号角；公会名 2~12 字、**全服唯一**；创建者 = 会长 |
| 人数上限 | **20 人**（含会长） |
| 公会面板 | 成员列表 + 在线状态；会长可踢人 / 转让 / 解散 |
| 据点锚点 | 会长在**当前所在位置**设置或迁移锚点（迁移消耗号角，冷却 24 小时） |
| 锚点间距 | 与**任意已有公会锚点**至少相距 `5000` 世界单位（否则全服会挤成一团） |
| 锚点可见 | 进入其视野的玩家能看到公会旗与名字（走 AOI 广播，不是全图可见） |
| 回到公会 | 成员按钮，`60 秒`冷却；**战斗中（3 秒内受过伤或出过手）不可用**，防逃跑滥用 |
| 入会方式 | 会长/成员的 6 位邀请码，或公会在面板里开放"可申请" |

- **公会锚点半径 300 内不生成怪** → 据点天然是安全区（沿用上一版"世界中心安全区"的思路）。
- 后续可扩：公会等级、公会任务、公会商店、公会排行。（首版只做"建会 + 锚点 + 回城 + 成员管理"）

## 11. 账号与存档

| 端 | 登录方式 | 说明 |
|---|---|---|
| 抖音小游戏（**唯一端**，决策 #7） | `tt.login()` → code → 服务端换 `openid` | **不需要账号密码**：抖音身份就是账号 |
| 开发期自测 | 本地存档（不发网络请求） | 阶段 A 先在本地把玩法跑通，阶段 B 再接账号 |

- 服务端统一账号表：`account(id, platform, platform_uid, nickname, created_at)`。
- 存档内容：等级 / 经验、货币、背包与已穿装备、宝箱计数与保底计数、最后位置、公会归属。
- **无网络时**：阶段 A 用本地存档先把玩法跑通；接入服务端后改为"断线可重连、离线不产出"（决策 #6：不做离线收益）。

## 12. 首版范围（明确"不做什么"）

**做**：竖屏适配 · 摇杆移动 · 无限地图与视野裁剪 · 自动战斗（含**全服共享怪 + 按最高伤害结算奖励**） · 4 种怪 + 难度分带 · 经验升级 · 六阶宝箱 · 装备穿戴与战力对比 · **四个技能键（A5：横扫 / 疗愈 / 穿刺 / 旋风，冷却 + 自动释放）** · 本地存档 → 账号云存档（抖音云）→ 附近玩家**与别人的怪**可见 → 公会（创建 / 锚点 / 一键回城 / 成员管理）。

**不做（首版）**：**H5 发行版**（决策 #7） · 自动寻路 · 技能连招 / 技能升级 / 天赋与符文（A5 只做四个固定技能键，见 §15） · 真实支付（决策 #3） · 组队副本 · 公会战 · 交易行 · 排行榜 · 离线收益（决策 #6） · 聊天（公会频道排在公会之后） · 强化/镶嵌/重铸 · 宠物 · 时装外观 · 抢怪缓解机制（仅预留开关，见 §4.1）。

## 14. 阶段 A4 的变更（2026-09-30，已落地：见 `04-decisions.md` #10）

> 这一节只写**用户可见的规则变化**，不重复实现细节。数值一律还是 `shared/balance.json` 一处。

**界面**

- **面板不再是全屏**：背包 / 商城 / 公会 / 设置 / 营地 都是一张**约占 1/3 屏面积**的卡片，
  右上角有 ✕，内容超出时在卡片内上下拖动滚动。
- **打开面板时游戏不停止**：世界照旧模拟，玩家照旧能推摇杆走位（卡片外的触摸给摇杆与右下功能键）。
  代价：站着开箱会被怪打 —— 这是玩家自己的选择，取代了 #8d 里"阶段 A 先暂停"的临时方案。
- **右下功能键**从 4 个变 5 个（多了「自动」），站在营地里再多一个「营」；经验条移到**画面最下方**，
  功能键整体抬高让位。
- **左上角**是头像 + 角色名 + 等级（头像由角色名与等级确定，程序自绘）；**玩家头顶**有角色名 + 血条；
  最下方是经验条。

**账号（进游戏之前的三块屏）**

- 标题 → 登录 → 创建角色。登录优先走抖音账号（`tt.login` → 服务端 `code2session` → openid），
  任何一环失败都**降级成本机离线账号**，绝不因为网络问题卡住进游戏。
- 创建角色就是"起个昵称"：2~12 个字符，只允许中文 / 字母 / 数字 / 下划线，保留名不给用。
- **昵称不能重复**是两层：本机注册表（离线立刻给提示，且**改名刷号不释放**旧昵称）+ 服务端 `POST /api/name`
  （跨设备去重）。服务端不可达时降级为仅本机去重，并在界面上写明。

**自动战斗（按钮）**

- 右下「自动」是开关，状态随存档。开启后：**自动走向视野内最近的怪**，进攻击距离站住；
  出手本来就是自动的（§4）。
- 摇杆只要推着就**手动优先**，随时可以接管。
- **技能系统仍然不做**（§12 的"不做"清单没变）：自动战斗 = 自动走位 + 自动出手。

**打击感与声音**

- 每次出手有斩击弧线（暴击多四道光刺）；命中**顿帧** 45ms、暴击 110ms、挨打 30ms；
  暴击**震屏** 26px/240ms、挨打 12px/150ms，并伴随短震动。
- 音效 8 个 + BGM 1 条，全部由 `tools\gen-minigame-sfx.mjs` **合成**（不引入外部素材）；
  设置面板可以分别关掉音效 / 背景音乐 / 震动，改完立刻生效并存进存档。

**营地（原点）**

- 营地现在是**交互入口**：点右下「营」可以治疗（按**缺失血量**收金币）、进商城、回营地中心（短冷却、
  战斗中禁用）、回公会锚点。
- **营地是真正的安全区（A6 起）**：巢穴落在**营地半径 900** 内的怪**不装载**（连同它背后那一片都不刷），
  已经在外面的怪一旦闯进半径就被推回边界并转身回家。于是在营地里治疗、看背包、开箱都不会被咬。
  实现上过滤发生在**装载层**（`14-world.loadChunk`），`05-spawn` 的生成流一个字没动 ——
  **世界指纹仍是 `e9802f11`**（跨端确定性建立在生成层）。

## 15. 阶段 A5 的变更（2026-09-30，已落地：见 `04-decisions.md` #11）

> 只写**玩家可见的规则变化**；数值依旧只在 `shared\balance.json`（新增一个 `skills` 块）。

**四个技能键（用户要求"做四个技能栏"）**

- 画面右下、功能键**左侧**多一排**四个技能键**：键面是一个大字，圈下写着技能名。

  | 键 | 名字 | 解锁 | 冷却 | 作用 |
  |---|---|---|---|---|
  | 斩 | 横扫 | Lv.1 | 4 秒 | 打身边 210 范围内的所有怪（1.6 倍攻击） |
  | 疗 | 疗愈 | Lv.4 | 22 秒 | 立刻回复生命上限的 40%（不会超上限） |
  | 刺 | 穿刺 | Lv.7 | 7 秒 | 打射程 420 内最近的一只（2.6 倍攻击，击退更远） |
  | 旋 | 旋风 | Lv.10 | 12 秒 | 打身边 330 范围内的所有怪（1.1 倍攻击） |

- **点一下放**：可用时键是亮的；冷却中压一层扇形暗罩、圈里读秒；没到等级画成"锁 + Lv.n"。
- 两次技能之间有 `300ms` **公共冷却**：点太快会提示"手速太快"，避免四个键在同一瞬间全放出去。
- **自动战斗时会自动放技能**（A4 的要求"自动战斗时不仅自动出手，还要自动释放技能"，A5 补齐）：
  按从左到右的顺序挑第一个能用的；治疗只在血量低于 `60%` 时放，伤害技要有怪在打击范围内才放（不空放）。
- 技能伤害与普攻**共用一份公式**（攻击 × 倍率之后仍然是 `max(1, 攻击 − 目标防御 × 0.6)`）；
  技能打出的伤害照样记在我头上 —— 用技能抢到的怪，经验与宝箱仍按"累计伤害最高"结算（决策 #1）。
- 冷却**不进存档**：重登游戏技能全部可用。它只是"这一刻能不能放"的手感数据，不是资产
  （也不给"改表刷冷却"留口子）。

**音效**

- 新增两个合成音效：`cast`（放技能）与 `mend`（治疗），于是共 **10 个音效 + 1 条 BGM**。
  技能命中不再叠播普通命中音 —— 一声 cast 已经够了。

## 16. 阶段 A6 的变更（2026-09-30，已落地：见 `04-decisions.md` #12）

> 只写**玩家可见的规则变化**；数值依旧只在 `shared\balance.json`（新增 `equipment.catalog` 等键）。

**装备与外观（用户要求"宝箱开出装备 + 每阶各十件 + 穿戴改人物外观 + 装备内观 + 等级划分 + 属性系统"）**

- **四个部位**：武器 / 衣服 / 鞋子 / 饰品（原来的头盔与手套并入衣服）。
- **六阶各 10 件，共 60 件有名有姓的装备**（木剑 → 铁剑 → 精铁长剑 → 龙牙巨剑 → 霜月神剑 → 天命之剑）：
  开箱先在**该阶的 10 件里抽一件**，再按等阶抽词条 → 于是每一件都有名字、有造型、有自己的等级门槛。
- **等级不够穿不上**：门槛 = `1 + (阶-1)×3 + floor(阶内序号/4)`（1 阶 Lv.1~3，6 阶 Lv.16~18）。
  开箱的"自动穿上"会跳过穿不上的（只进背包），手动点会被拒并提示还差几级。
- **同阶内越靠后越强**（`+2%` 一件，第 10 件 +18%）：同阶也有"更好的那一件"值得再刷。
- **穿什么就像什么**：武器有 8 种造型（剑 / 巨剑 / 短刃 / 枪 / 斧 / 锤 / 法杖 / 镰）、
  衣服有 6 种款式（长袍 / 皮甲 / 布衣 / 锁子甲 / 板甲 / 披风）、鞋子 4 种、饰品 4 种（项链 / 戒指 / 宝珠 / 头冠），
  加上各自的配色，全部**程序自绘**在角色身上；**背包里用同一份数据画成内观图标**（阶色边框）。
- **人物属性系统**：设置 / 背包里的「角色属性」面板逐项列出攻击 / 生命上限 / 防御 / 攻速 / 暴击率 /
  暴击伤害 / 增伤 / 减伤 / 移动速度 / 拾取范围 / 经验加成 / 金币加成，逐项写清"等级基础 + 装备加成"。
- **背包装备栏**列出四个部位（空位显示部位剪影），点一下**脱下**（装备回背包，外观立刻变回没穿的样子）。

**Q版与视角（用户要求"人物和地图更细致、扩大视角分辨率、做 Q版可爱的角色与更细的地图 UI"）**

- **视角拉远 20%**（`view.cameraZoom = 0.8`）：只缩放**世界层**，视野每边多看 25%，UI 尺寸不变。
- **Q版角色**：大头（头几乎和躯干一样大）+ 大眼睛（白眼球 + 黑瞳 + 高光）+ 腮红 + 呆毛；
  四只怪也换了同一套"大眼睛"画法。动画相位仍只由逻辑时间推出来。
- **更细的地图**：地表色块从 4×4 变 **5×5**，每个 chunk 再加一撮**土斑 / 草籽**细纹；
  营地广场中心多了石环与菱形刻纹。**同色图元攒成一条路径一次画完**，所以细节更多而落笔更少
  （营地那一帧从 786 降到 **651**，最坏 660 对预算 900）。

**UI 图标与一个 bug（用户要求"每个 UI 按钮都要有对应图标"+"登录注册页面按钮上没有文字"）**

- **每个按钮都有图标**：右下功能键（箱 / 包 / 会 / 营 / 设 / 自动）、四个技能键（横扫 / 疗愈 / 穿刺 / 旋风，
  技能键保留「斩 / 疗 / 刺 / 旋」小徽章）、面板行（装备 = 内观图标，功能 = 对应图形）、
  登录页（登录 / 清账号 / 输入昵称 / 换一个 / 创建角色）；图标与角色外观都是 `16-icons.js` 里的自绘图元。
- **修掉登录 / 注册页面按钮没有文字**：按钮以前只画了底与边框，文案靠别处补而漏掉了。
  现在**按钮自己负责自己的字与图标**（`G.LOGIN.painted`），并新增断言盯着它
  （假 canvas 记下每一段 `fillText`，逐个比对按钮文案）。
